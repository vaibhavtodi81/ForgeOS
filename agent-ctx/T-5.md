## Contract mismatches + resolutions
1. Saved-notice query under hash routing: the form navigates to `#/projects/:id/logs/:logId?saved=created`; App.tsx passes the segment including `?saved=…` as the `logId` prop. Resolved inside ProjectLogDetailPage by splitting the query off the prop (no App.tsx change — foundation-owned).
2. Backend labour/machinery hours require `> 0` (original client allowed 0) — client validation tightened to match; server messages still surface inline if bypassed.
3. Backend validation errors return 400 (original code had a 422 branch from the old Express API) — branch removed; 400 falls through to `error.message`.
4. `/audit-logs` list response is `{items, total, page, limit}` inside `data` (not a bare array with meta) — auditApi returns `response.data` directly, matching.
5. Milestone status select options and audit filter options are built from live API values (stats/byAction + observed items) — zero hardcoded option lists.
6. `setPage(1)`-on-filter-change effect and option-accumulation effects tripped `react-hooks/set-state-in-effect` — restructured: page reset moved into filter handlers/debounce callback; filter options derived via `useMemo` from `result`/`stats`.
